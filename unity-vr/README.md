## Build and verify

Run these steps from PowerShell with Unity closed for this project.

```powershell
./build.ps1 -Step Prepare
./build.ps1 -Step Bake
./build.ps1 -Step Test
./build.ps1 -Step Android
```

Prepare regenerates `Assets/FrameLab/Scenes/Leichhardt.unity` from the imported models and the scene builder. It configures the mobile renderer, XR rig and Android settings, checks destination clearance, and writes overview and interior previews under `Builds/Preview`. Make repeatable scene changes in `Assets/FrameLab/Editor/FrameLabBuild.cs`.

Bake computes eight furnished/empty lightmap states for every wall/roof visibility combination. Direct sunlight and broad neutral fill are fully baked, with a wider sun angle for soft shadows and 24 texels/metre on the building. The large plain ground receives baked building shadows at reduced lightmap density. Fill lights are used only in the enclosed state; the exposed states receive daylight directly. Visibility changes swap the matching maps, avoiding hidden-wall and hidden-roof shadows. Static building meshes do not cast runtime shadows. The movable window study has its own light, active only in the study. Prepare regenerates the scene and therefore must be followed by Bake.

Test exercises all room arrivals, automatic narration, walk-through doorway clearances and thresholds, three storage apertures, wall visibility/collision, eight lighting states, retained floor support, full-panel visibility, A-button press/release behaviour, and the window study. A cupboard divider behind a storage opening is not treated as a walk-through obstruction. Study checks cover continuous slider input, non-overlapping separated components, nine narrated hotspots, isolation, zoom, rotation, reset and a simulated XRI grab. Completion, mute and restart are also covered. The scene sun and five static reflection textures are checked. The test output is `Builds/Preview/session-tests.txt`; room and study renders are saved beside it. The test records the known Unity editor search-index startup exception separately; gameplay and rendering errors still fail the run. Physical controller tracking, stereo comfort and sustained performance must be checked on the headset.

Android writes the development APK to `Builds/Android/Leichhardt-PICO.apk`. Logs are under `Logs`. The initial APK uses development signing. Set the stable release key through the project's build process before classroom distribution.
