# Frame Lab — Leichhardt

## Visual revision

The explorer now opens at the enclosed roof stage. Detailed lighting adds studio environment reflections, directional soft-shadow mapping, a shadow-receiving ground plane, procedural member-aligned timber grain, brick coursing and transmissive glass. The lighting switch disables shadows and procedural finishes, lowers pixel density and uses cheaper glazing for lighter devices. These are illustrative finishes, not selected products.

The export now uses an all-visible evaluation layer. This corrects the cutaway-hidden members previously exported as unit cubes at the origin. Face winding is corrected on export copies, and the camera depth range is tightened to reduce depth artefacts. No audited building dimensions were corrected. Regression tests reject origin geometry and below-datum roof sheets and require texture coordinates/material metadata.

Material tests check the current Three.js shader insertion points and quality settings; they are not a GPU/browser visual test. Browser/device visual acceptance testing is still outstanding.

Student-facing 3D construction explorer, based on the saved Blender enclosure model. All details remain provisional pending teacher review.

## Content

- Four teaching reveal stages: frame, wrap, cladding, main roof.
- Enclosure cutaway, layer visibility and selection, mouse/touch orbit and keyboard-accessible camera buttons.
- Window, eaves and floor-edge studies with exploded layers and discussion prompts.
- Source basis and assumptions available in the Basis tab. No original drawing PDFs are distributed.

## Development

`npm install`, then `npm run dev`. `npm run build` makes a static export in `dist/client`. `npx tsc --noEmit` checks types. `node --experimental-strip-types --test lib/explorer.test.ts` checks navigation and loads every GLB without browser automation.

Build with Node 22 LTS on Windows. Node 24.12 triggered a native libuv shutdown assertion after prerender; Node 22 completed successfully. A one-off command is `npm exec --yes --package=node@22 -- node node_modules/vinext/dist/cli.js build`.

Models and metadata are generated by `../scripts/build_learning.py` from the saved enclosure Blender file. Keep exports and manifest together. Blender materials are simplified for web display; the frame geometry is preserved in the source revision.

No student accounts, tracking, database, uploads or student records are implemented. Hosting access is private for the owner until explicitly shared. The application is static; no server functions or image processing run in production.

The optional `navigate_construction_study` WebMCP tool uses the same visible page state. Unsupported browsers ignore it. A supported live WebMCP validation context was unavailable in this run, so registration and live state transitions are not claimed as verified. Input validation is covered by the local tests.

Validation scope: type checks, static build, model parsing/metadata, navigation and visibility tests, plus visual inspection of the Blender renders. Browser interaction, responsive visual and touch-device QA were not performed in this run. Review these before a class release.

The scaffold's full lint run reports pre-existing diagnostics in vendored UI components; they were not edited as part of this work.

The scaffold's dependency audit currently reports 11 advisories, primarily build/dev-server and server-side packages. Static deployment does not ship an executable Node/Workers server. Keep local development loopback-only; update and re-audit the toolchain before enabling any server-backed features. No blanket claim of security review is made.
